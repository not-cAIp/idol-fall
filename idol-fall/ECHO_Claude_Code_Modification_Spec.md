# ECHO / 偶像解谜项目 — Claude Code 修改规格

> 用途：直接提供给 Claude / Claude Code 作为当前版本的修改需求。
> 原则：以下内容以本文件为最新版本；与旧设定冲突时，以本文件为准。

## 1. 全局名称修改

在 **ECHO 范围内全局搜索并替换**：

- `NOVA5` → `NOV5`
- `NOVA7` → `F4ever`
- `HX_PROD` / 误写的 `XH_PROD` → `新_PROD`
- `HX_404` 保持不变。

需要检查群名、群名历史、文章标题、正文、账号资料、工作群、物料署名、隐藏文本等所有位置，避免残留旧名称。

群聊相关文案统一为：

```text
F4ever成员群（4）
群成员：4 · 另有 1 个账号状态异常
‹ 查看群名变更记录

出道预备A组（5） — 最早建群时的名字。
NOV5（5） — 确定组合方向后改的。
项目确认群（5） — 公司正式确认项目后又改了一次。
F4ever成员群（4） — 最后一次改名，成员数从 5 变成了 4。第五个人的账号从这之后就一直显示『已注销』。
```

旧采访标题也相应改为：

```text
《F4ever林安：我最怀念的是没有名字的夏天》（节选）
```

正文：

```text
小时候家里人都叫他『安仔』，这个称呼他自己好像也没打算改掉。聊起练习生那几年，他说印象最深的还是最早分到的那间练习室，编号07，『墙上贴的镜子到现在想起来都觉得冷』。

2019年出道，他说起这件事时停顿了很久：『最早的时候，房间里一直有五个人。』记者追问是什么意思，他笑了笑没有细说，转而聊起别的话题。
```

## 2. 删除不自然的“返回超话”导航

删除 Bubble、ECHO 线索页、HX_404 / 新_PROD 相关页面等调查页面下方的：

- `返回超话`
- `返回超话继续调查`
- 任何功能等同、会直接提示玩家下一步去超话的按钮

不要通过 UI 明示玩家“现在应该回哪里调查”。返回应依赖正常浏览器/应用导航或自然的信息架构。

## 3. Pt1 推理流程调整

### Step 1

不要再问玩家：

> 公司是不是对的？

第一步直接要求玩家根据当前证据判断时间范围，正确结论应至少为：

> `23:52之后`

### Step 2

之后再利用 Bubble 中**更晚发送的消息**进一步缩小时间。

提示语可使用：

> `你能继续锁定时间吗？`

### 跳步判定

如果玩家在 Step 1 就直接输入/推导出了 Step 2 所要求的最终精确答案：

- Step 1 自动通过；
- Step 2 也同时视为通过；
- 不要强迫玩家重复已经正确完成的推理。

# 7. ECHO 主密码：旧新闻网页线索链

## 核心设计

不要让林安超话粉丝帖直接告诉玩家“狗的生日”。

将密码线索设计成一个 **跨页面的旧互联网考古过程**：

```text
林安超话粉丝帖
    ↓
分享的旧娱乐新闻
    ↓
第一页：林安小时候上节目唱歌的视频
    ↓
页面底部不显眼的“下一页”
    ↓
第二页：林安和小时候的金毛
    ↓
透露金毛生日 + “这是对他最重要的日子”
    ↓
玩家将日期与其他密码规律结合
```

## 7.1 超话粉丝帖

在林安超话中加入一条自然的考古粉丝帖，例如：

```text
【考古】救命谁挖出来的这个😭 林安小时候居然上过这个节目
🔗「童声舞台上的小林安：一首《××》唱哭现场观众」
```

文案可以根据现有世界观润色，但这里**不能提狗、狗生日或 ECHO 密码**。

新闻链接必须可以真实点击。

## 7.2 新闻站视觉

制作一个虚构的 2010 年代早期中文娱乐门户网站，例如：

- 星闻娱乐
- STAR娱乐
- 或其他虚构站名

视觉语言参考 2010–2013 年新浪娱乐 / 搜狐娱乐 / 网易娱乐等旧门户，但**不要 1:1 使用真实网站 Logo 或直接冒充真实网站**。

建议 UI：

- 白色背景；
- 顶部密集频道导航；
- 蓝色文字链接；
- 较窄正文栏；
- 小号灰色发布日期和来源；
- 4:3 低清电视截图；
- 旧式视频播放器占位；
- “打印 / 收藏 / 相关新闻”等旧网页元素；
- 页面底部旧式分页。

## 7.3 新闻第一页

标题可类似：

```text
《童声嘹亮》往期片段曝光 童年林安登台演唱
```

内容只围绕：

- 林安小时候参加节目；
- 上台唱歌；
- 一张 4:3、低清电视节目截图；
- 可显示类似：

```text
视频：林安童年舞台演唱片段 02:14
```

**第一页绝对不要出现狗或生日。**

## 7.4 隐蔽分页

在第一页底部加入符合旧门户习惯的分页，例如：

```text
上一页   1   2   下一页 >
```

其中：

- `2` 可以点击；
- `下一页 >` 也可以点击；
- 不要做成现代游戏风格的大型 CTA；
- 让它看起来只是旧新闻网页本来的分页机制。

也可以显示类似：

```text
下一页 - 节目录制后台的童年照片
```

但不要在标题里直接暴露“狗生日”。

## 7.5 新闻第二页

第二页才出现林安和小时候金毛的照片/内容。

建议新闻正文自然写成类似：

```text
节目录制间隙，林安向记者展示了随身带着的家庭照片。照片里，他抱着从小一起长大的金毛“XX”。

被问到一年里最喜欢哪一天，他没有说春节或自己的生日，而是指着照片笑称：“X月X日，它生日。这个对我最重要。”
```

具体狗名和日期应与最终谜题答案一致。

玩家应该自己意识到这个日期可能是 ECHO 密码线索，而不是由系统弹窗解释。

# 8. ECHO 员工群密码

ECHO 中的“员工群”不能直接进入。

玩家点击员工群后，应看到真实的密码输入界面，需要输入内部密码才能进入。

## 8.1 密码规律线索：陈

将密码规律藏在“陈”的备忘录账号/页面中。

不要再使用模糊的：

> 公司早期给群聊设置密码总是同一个套路……

最新版应更明确地表现为陈的吐槽：

```text
怎么都是原名_生日
```

下方出现 `manibeeo` 的回复：

```text
你带的都这么糊，谁没事去黑账号
```

这段内容必须真实存在于玩家能浏览到的账号/备忘录/评论界面中，而不是游戏旁白。

## 8.2 推理方式

这条线索只负责告诉玩家密码的**构造规则**：

```text
原名_生日
```

人物的原名和生日应由其他线索提供。

不要在员工群登录页直接展示完整密码。

# 9. HX_404 / 新_PROD 视觉证据链

这部分不要再使用文字描述：

> “这里有一张照片……”

必须做成玩家能**真实点击账号并查看图片**的内容。

## 9.1 HX_404

账号资料：

```text
HX_404 的资料（已注销）
项目编号 H-X-04 ｜ 姓名：贺寻
```

玩家应可以点进这个已注销账号的残留资料页。

### 置顶相册

账号置顶相册里实际制作并展示一张图片：

- 一根麦克风线；
- 接口处缠着一圈**银色交叉胶带**；
- 看起来像本人为了防止器材拿混而做的标记。

图片配文：

```text
自己做的记号，不然天天跟别人拿混
```

这张图必须是真正的图片素材，而不是纯文字说明。

## 9.2 新_PROD

所有旧 `HX_PROD` / `XH_PROD` 统一改成：

```text
新_PROD
```

周年物料署名：

```text
『晏星的七年留言』周年企划 · 素材执行：新_PROD
```

对应周年物料/幕后花絮也要做成可实际查看的图片。

花絮画面中，工作人员使用的麦克风线接口也缠有：

> 一圈银色交叉胶带

打法与 HX_404 旧相册照片中的标记一致。

**不要直接写“这证明新_PROD就是贺寻”。**

让玩家自己通过视觉比对建立联系。

## 9.3 新_PROD 的进入方式

`新_PROD` 应存在于 ECHO 的另一个工作群中。

该群可以包含：

- 林；
- 新_PROD；
- 不重要的经纪人；
- 不重要的工作人员；
- 其他用于增加真实感的普通成员。

玩家可以从：

```text
工作群 → 群成员 / 消息中的账号 → 新_PROD 账号
```

真实点进去。

不要直接提供一个“查看新_PROD线索”的游戏按钮。

# 10. 陈的经纪人文件夹

当剧情提供“陈的经纪人文件夹”时，不要因为玩家选择了这条调查路径就自动解锁。

账号/角色：

```text
陪你走到最后
```

只负责向玩家提供文件夹密码：

```text
0913run
```

正确交互流程必须是：

```text
玩家获得 0913run
    ↓
找到陈的经纪人文件夹
    ↓
文件夹显示密码输入框
    ↓
玩家手动输入 0913run
    ↓
验证成功
    ↓
文件夹解锁
```

不要把“选择路径”和“解锁文件夹”合并。

# 11. 交互设计总原则

本轮修改最重要的方向是：**把“游戏告诉玩家线索”改成“玩家自己在一个真实可浏览的网络环境里找到证据”。**

因此：

1. 如果文案写“网页链接”，链接就必须真的能点。
2. 如果说某账号有照片，玩家就必须能点进账号看到照片。
3. 如果线索藏在评论里，就真的做出帖子和评论区。
4. 如果线索来自下一页，就真的制作第一页和第二页，并让分页可点击。
5. 如果某群需要密码，就真的显示密码输入界面。
6. 如果玩家获得的是密码，不要自动替玩家输入或直接解锁。
7. 不要使用“返回超话继续调查”等元游戏导航提示。
8. 尽量让线索分布在不同来源，玩家需要自行组合，而不是单页面直接给结论。
9. 对已经推导出更后一步答案的玩家允许跳步，不要强制重复推理。
10. 所有旧名称必须做全局一致性检查。
